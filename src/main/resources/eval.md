# UI Agent — Video Analysis Eval Framework Requirements

## Overview
Evaluate the quality of navigation steps generated by the UI Agent from video recordings.
Two modes: Benchmark Eval (offline) and Real-time Confidence (online).

---

## Goals
- Detect hallucinated steps (steps that never happened in video)
- Detect missing steps (steps that did happen but were not generated)
- Detect wrong step order
- Detect wrong element labels (e.g., "Login" vs "Sign In")
- Detect credential leaks in PLACEHOLDER mode
- Detect incorrect pagination pattern (AGGREGATION mode only)
- Provide LLM-as-Judge scoring using existing BedrockAnthropicClient
- Provide real-time confidence score for new video uploads

---

## Two Modes

### Mode 1 — Benchmark Eval (Offline)
- Purpose : Measure model/prompt quality over known videos
- When    : Before deploying new Claude model, after prompt changes,
            after VideoFrameExtractor config changes, regression testing
- Input   : 8 known videos + ground truth steps
- Output  : Detailed per-case scores + aggregate report
- Ground  : Human-written ground truth in benchmarks.json

### Mode 2 — Real-time Confidence (Online)
- Purpose : Confidence signal for brand new video uploads
- When    : Every time a user uploads a new video via UI or CLI
- Input   : Newly uploaded video (no ground truth available)
- Output  : Confidence score (0-100) + warnings + recommendation
- Ground  : No ground truth — LLM judges self-consistency

### benchmark/EvalMetrics.java

#### Purpose
Pure static metric calculations.
No I/O, no LLM calls, fully unit-testable.

#### Overall Score Weights
```
stepRecall          30%
stepPrecision       20%
stepOrderScore      15%
labelAccuracyScore  15%
placeholderScore    10%
paginationScore     10%
```

#### Methods

```
computeStepRecall(gtSteps, generatedSteps)
  Input  : List<String> gtSteps, List<String> generatedSteps
  Output : double 0.0-1.0
  Logic  : GT steps found in generated / total GT steps
           Uses fuzzy Jaccard match with threshold 0.6
           A GT step is "found" if any generated step scores >= 0.6

computeStepPrecision(gtSteps, generatedSteps)
  Input  : List<String> gtSteps, List<String> generatedSteps
  Output : double 0.0-1.0
  Logic  : Generated steps matching GT / total generated steps
           Low precision = hallucinated steps present
           Uses same 0.6 Jaccard threshold

computeStepOrderScore(gtSteps, generatedSteps)
  Input  : List<String> gtSteps, List<String> generatedSteps
  Output : double 0.0-1.0
  Logic  : Build list of GT indices for each matched generated step
           Count concordant vs discordant pairs (Kendall Tau)
           Normalize: (tau + 1.0) / 2.0
           Returns 1.0 if fewer than 2 matched steps

computeLabelAccuracy(gtSteps, generatedSteps)
  Input  : List<String> gtSteps, List<String> generatedSteps
  Output : double 0.0-1.0
  Logic  : For each GT step find best matching generated step
           Average the similarity scores of matched pairs
           Returns 0.0 if no matches found

computePlaceholderScore(navigationGoal, mode, credentialLeaks)
  Input  : String navigationGoal, String mode, List<String> credentialLeaks (mutable)
  Output : double 1.0 or 0.0
  Logic  : Return 1.0 immediately for LITERAL mode
           Scan navigationGoal for email patterns (contains @)
           Scan for long strings not wrapped in {braces} (length >= 6)
           Populate credentialLeaks list with found violations
           Return 1.0 if clean, 0.0 if any leak found

computePaginationScore(gt, generated, taskType)
  Input  : PaginationGT gt, PaginationPattern generated, String taskType
  Output : double 0.0-1.0
  Logic  : Return 0.0 for PROVISIONING taskType
           type match = 1.0 exact, 0.0 mismatch — weight 50%
           selectorHint fuzzy match — weight 30%
           description fuzzy match — weight 20%

computeOverallScore(result)
  Input  : EvalResult result
  Output : double 0.0-1.0
  Logic  : Apply weights defined above
           PROVISIONING: redistribute pagination 10% to stepRecall

detectHallucinatedSteps(gtSteps, generatedSteps)
  Input  : List<String> gtSteps, List<String> generatedSteps
  Output : List<String> — steps in generated not matching any GT step
  Logic  : For each generated step check if any GT step scores >= 0.6
           If no match found add to hallucinated list

detectMissingSteps(gtSteps, generatedSteps)
  Input  : List<String> gtSteps, List<String> generatedSteps
  Output : List<String> — GT steps not found in generated output
  Logic  : For each GT step check if any generated step scores >= 0.6
           If no match found add to missing list

detectCredentialLeaks(navigationGoal)
  Input  : String navigationGoal
  Output : List<String> — detected credential values
  Logic  : Find all email patterns via regex
           Find quoted strings not containing {Token} with length >= 6
           Return all found violations
```

### shared/LlmJudge.java

#### Purpose
LLM-as-Judge for both benchmark and real-time modes.
Uses existing BedrockAnthropicClient.
Works with ground truth (benchmark) and without (real-time).

#### Judge Prompt Inputs
```
Benchmark mode (with GT):
  - Ground truth steps (ordered list)
  - Generated steps (ordered list)
  - Task type (AGGREGATION or PROVISIONING)
  - Mode (PLACEHOLDER or LITERAL)
  - Generated paginationPattern (AGGREGATION only)

Real-time mode (without GT):
  - Generated steps (ordered list)
  - Task type
  - Mode
  - Generated paginationPattern (AGGREGATION only)
  - Target URL (if available)
```

#### Judge Response Schema
```json
{
  "correctness":          0-10,
  "order":                0-10,
  "hallucination":        0-10,
  "label_quality":        0-10,
  "placeholder":          0-10,
  "overall":              0-10,
  "reasoning":            "string explanation",
  "hallucinated_steps":   ["step1", "step2"],
  "missing_steps":        ["step1"],
  "confidence_score":     0-100,
  "warnings":             ["warning1", "warning2"],
  "recommendation":       "TRUST|REVIEW|CAUTION"
}
```

#### Recommendation Thresholds
```
TRUST    confidence >= 85 and no warnings
REVIEW   confidence 60-84 or minor warnings
CAUTION  confidence < 60 or significant issues
```

#### Methods
```
judge(EvalCase evalCase, VideoAnalysisResult generated, BedrockAnthropicClient bedrock)
  Purpose : Benchmark mode — judge with ground truth
  Input   : full eval case (has GT), generated result, bedrock client
  Output  : JudgeResult record
  Logic   : Build prompt with GT steps + generated steps
            Call bedrock.invokeWithVision() with null screenshot (text only)
            Parse JSON response into JudgeResult

judgeWithoutGroundTruth(VideoAnalysisResult generated,
                        String taskType, String mode,
                        BedrockAnthropicClient bedrock)
  Purpose : Real-time mode — judge without ground truth
  Input   : generated result, task type, mode, bedrock client
  Output  : JudgeResult record
  Logic   : Build self-consistency prompt
            Check for known UI flow patterns
            Check placeholder compliance
            Check step count reasonableness (< 2 or > 20 is suspicious)
            Check logical flow (email before password, login before navigation)
            Call bedrock.invokeWithVision() with null screenshot
            Parse JSON response into JudgeResult
```

### benchmark/VideoAnalysisEvaluator.java

#### Purpose
Main runner for benchmark eval.
Orchestrates full pipeline per case and produces report.

#### CLI
```
./gradlew runEval
  --benchmarks=./src/main/resources/eval/benchmarks.json
  --case=eval_001          (optional — run single case only)
  --skip-judge             (optional — skip LLM judge, faster and cheaper)
  --output=./eval-reports  (optional — output directory)
```

#### Flow Per Case
```
1.  Load EvalCase from benchmarks.json
2.  Extract frames via VideoFrameExtractor (existing)
3.  Build VideoAnalysisRequest from case.mode + case.taskType (existing)
4.  Build prompts via VideoAnalysisPrompt.build() (existing)
5.  Call BedrockAnthropicClient.invokeWithMultipleImages() (existing)
6.  Parse response via VideoAnalysisResult.parse() (existing)
7.  Compute automated metrics via EvalMetrics
8.  Call LlmJudge.judge() unless --skip-judge
9.  Build EvalResult via EvalResult.builder()
10. Accumulate results
11. Generate EvalReport
```

#### Integration Points With Existing Code
```
VideoFrameExtractor.extractFrames()         step 2
VideoAnalysisRequest.aggregation()
  or .provisioning()                        step 3
VideoAnalysisPrompt.build()                 step 4
BedrockAnthropicClient
  .invokeWithMultipleImages()               step 5
VideoAnalysisResult.parse()                 step 6
PocConfig (existing)                        config
TokenUsage (existing)                       accumulate cost
```

#### Error Handling
```
Video file not found      → skip case, record issue, continue
Frame extraction fails    → skip case, record issue, continue
Claude call fails         → skip case, record issue, continue
JSON parse fails          → record parse error in issues list
Judge call fails          → record 0.0 judge scores, continue
```

### realtime/ConfidenceEvaluator.java

#### Purpose
Real-time confidence scoring for new video uploads.
No ground truth available.

#### Methods
```
evaluate(VideoAnalysisResult generated,
         String taskType,
         String mode,
         BedrockAnthropicClient bedrock)
  Input  : generated result, task type, mode, bedrock client
  Output : ConfidenceResult
  Logic  : Run automated pre-checks (see below)
           Call LlmJudge.judgeWithoutGroundTruth()
           Combine automated checks + judge score
           Build ConfidenceResult

Pre-checks (automated — no LLM needed):
  stepCountCheck
    FAIL if steps < 2 (too few — suspicious)
    FAIL if steps > 25 (too many — likely hallucination)
    WARN if steps == 1

  placeholderCheck
    Only for PLACEHOLDER mode
    FAIL if any credential leak detected via EvalMetrics.detectCredentialLeaks()
    Add each leak as a warning

  logicalFlowCheck
    WARN if no click or type step found at all
    WARN if AGGREGATION mode and no paginationPattern found
    WARN if paginationType is unknown
    WARN if targetUrl is blank

  stepFormatCheck
    WARN if any step is longer than 200 characters (likely malformed)
    WARN if steps contain numbered lists (1. 2. 3.) — wrong format
    WARN if steps do not contain "then" connector
```

#### Integration With Existing UI Flow
```
Current AggregationGenerateHandler flow:
  Upload video → generate steps → return to UI

New flow:
  Upload video → generate steps → ConfidenceEvaluator.evaluate()
              → return steps + ConfidenceResult to UI

Current GenerateHandler flow:
  Upload video → generate steps → return to UI

New flow:
  Upload video → generate steps → ConfidenceEvaluator.evaluate()
              → return steps + ConfidenceResult to UI
```
