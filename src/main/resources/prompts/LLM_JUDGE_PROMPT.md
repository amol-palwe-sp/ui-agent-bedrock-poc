# LLM Judge Prompt

**Source class:** `com.sailpoint.poc.uiagent.eval.shared.LlmJudge`  
**Used by:** Eval benchmark (`runEval`, `/api/eval/run`), Provisioning/Aggregation UI confidence scoring  
**Model call:** Text-only (no images) — compares two strings, no vision needed  
**Output:** A JSON object with numeric scores (0–10) and a recommendation

---

## When this prompt is used

The judge runs as a **second LLM call** after the main video analysis is complete. It receives the AI-generated navigation goal and (in benchmark mode) the human-written ground truth, then scores the quality.

There are two modes:

| Mode | Has ground truth? | Triggered by |
|------|------------------|-------------|
| **Benchmark** | Yes — compares generated vs GT | `runEval` / `/api/eval/run` (unless `--skip-judge`) |
| **Real-time** | No — holistic self-consistency check | Provisioning and Aggregation UI tabs after generate |

---

## System Prompt (shared by both modes)

```
You are an expert evaluator of UI navigation automation scripts.
Your job is to assess the quality of navigation steps generated by an AI agent
from video recordings. Be precise, fair, and consistent.
Always respond with valid JSON only — no markdown fences, no explanation outside JSON.
```

---

## Benchmark Mode — User Prompt

Built dynamically from the eval case and generated result. Representative rendered form:

```
You are evaluating a navigation goal script generated by an AI agent from a video recording.

TASK TYPE: AGGREGATION
MODE: PLACEHOLDER

GROUND TRUTH NAVIGATION GOAL:
enter "{Email}" in the Email or phone field, then click Next button, then enter "{Password}" in the Enter your password field, then click Next button, then wait for the Google Admin console to load and navigate to the Users list page this completes all steps — do not perform any further actions

GENERATED NAVIGATION GOAL:
enter "{Email}" in the Email or phone field, then click Next button, then enter "{Password}" in the Enter your password field, then click Next button, then wait for the Google Admin console to load and navigate to the Users list page, then this completes all steps — do not perform any further actions

GENERATED PAGINATION PATTERN:
  type: next_button
  description: The users table shows Page X of many at the bottom right with previous and next arrow buttons (< and >) to navigate between pages of results.
  selectorHint: button[aria-label='Go to next page']

EXPECTED PAGINATION PATTERN:
  type: next_button
  description: The users table shows Page X of many at the bottom right with previous and next arrow buttons (< and >) to navigate between pages.
  selectorHint: button[aria-label='Go to next page']

EVALUATION CRITERIA (compare the two goal strings above):
1. correctness (0-10): Does the generated goal cover the same actions as ground truth?
2. order (0-10): Are the actions in the same chronological order as ground truth?
3. hallucination (0-10): 10 = no invented actions; 0 = many actions not in ground truth.
4. label_quality (0-10): Do UI element labels (field names, button labels) match ground truth?
5. placeholder (0-10): Are credentials/dynamic values replaced with {Token} syntax instead of literal values?
6. overall (0-10): Holistic quality — would this script navigate the same UI workflow as ground truth?

For hallucinated_steps list the action phrases present in GENERATED but absent from GROUND TRUTH.
For missing_steps list the action phrases present in GROUND TRUTH but absent from GENERATED.

Respond ONLY with this JSON (no markdown, no extra text):
{
  "correctness": <0-10>,
  "order": <0-10>,
  "hallucination": <0-10>,
  "label_quality": <0-10>,
  "placeholder": <0-10>,
  "overall": <0-10>,
  "reasoning": "brief explanation",
  "hallucinated_steps": ["action phrase not in GT"],
  "missing_steps": ["GT action phrase not in generated"],
  "confidence_score": <0-100>,
  "warnings": ["warning message"],
  "recommendation": "TRUST|REVIEW|CAUTION"
}
```

> **Note:** `placeholder` criterion is only active for AGGREGATION + PLACEHOLDER cases. For PROVISIONING or LITERAL mode, the prompt instructs the judge to give a score of 10.

## Real-time Mode — User Prompt

Used when there is no ground truth (live UI scoring after generate). Representative rendered form:

```
You are evaluating a navigation goal script generated by an AI agent from a video recording.
There is NO ground truth. Give a holistic confidence score — do NOT enumerate every possible concern.

TASK TYPE: AGGREGATION
TARGET URL: https://admin.google.com/ac/users
STEP COUNT: 6

GENERATED NAVIGATION GOAL:
enter "{Email}" in the Email or phone field, then click Next button, then enter "{Password}" in the Enter your password field, then click Next button, then wait for the Google Admin console to load and navigate to the Users list page

PAGINATION PATTERN: type=next_button, description=The users table shows Page X of many at the bottom right with previous and next arrow buttons.

SCORING GUIDE:
- confidence_score 0-100: overall trustworthiness of this script
- overall 0-10: holistic quality
- correctness 0-10: plausible, complete UI workflow
- order 0-10: logical chronological sequence
- hallucination 0-10: 10=grounded actions, 0=invented/contradictory
- label_quality 0-10: specific, unambiguous UI element names
- placeholder 0-10: credentials use {Token} syntax (not literal values)

Only add warnings for clear structural problems: empty goal, impossible action order,
or completely missing required actions (e.g. no login steps before navigation).
Do NOT warn about specific label choices, individual credential values, or assumed missing navigation steps.

Respond ONLY with this JSON (no markdown, no extra text):
{
  "correctness": <0-10>,
  "order": <0-10>,
  "hallucination": <0-10>,
  "label_quality": <0-10>,
  "placeholder": <0-10>,
  "overall": <0-10>,
  "reasoning": "1-2 sentence holistic assessment",
  "hallucinated_steps": [],
  "missing_steps": [],
  "confidence_score": <0-100>,
  "warnings": [],
  "recommendation": "TRUST|REVIEW|CAUTION"
}
```

---

## Output format Claude must return (both modes)

```json
{
  "correctness": 9,
  "order": 10,
  "hallucination": 9,
  "label_quality": 10,
  "placeholder": 10,
  "overall": 9,
  "reasoning": "Generated goal matches ground truth closely. One minor extra halt clause present but functionally identical.",
  "hallucinated_steps": ["this completes all steps — do not perform any further actions"],
  "missing_steps": [],
  "confidence_score": 92,
  "warnings": [],
  "recommendation": "TRUST"
}
```

---

## How scores map to the UI and report

| Field | Used in eval report as | Threshold |
|-------|----------------------|-----------|
| `overall` | `judgeOverallScore` (0–10 displayed) | — |
| `correctness` | `judgeCorrectnessScore` | — |
| `order` | `judgeOrderScore` | — |
| `hallucination` | `judgeHallucinationScore` | — |
| `label_quality` | `judgeLabelScore` | — |
| `placeholder` | `judgePlaceholderScore` | — |
| `confidence_score` | Used to auto-set `recommendation` | ≥85 → TRUST, ≥60 → REVIEW, else CAUTION |
| `recommendation` | Shown in UI after override logic | TRUST / REVIEW / CAUTION |

---

## Skipping the judge

Pass `--skip-judge` to `runEval` or toggle **Skip Judge** in the Eval UI to omit this second LLM call. All judge fields will be `0.0` and `recommendation` will be empty in the report.
